Getting started

Rivers runs as a public testnet. Test RVRB comes from the faucet and has no value. Every product is its own site:

SiteUse it to
Rivers WalletHold, send, swap, stake, lend and borrow
Rivers ScanLook up transactions, accounts, tokens, validators and pools; launch a token
Rivers ConnectSend institution payments (members only)
Rivers ValidatorRun and manage a validator
Rivers CoreAdminister the network (foundation only)

Each site reads the network address from its own settings. A site can also be pointed at another network with ?rpc=, &faucet= and &indexer= in its address, which is how developers use a local network.

Wallet

Create a wallet

  1. Open Rivers Wallet and choose Create.
  2. Write the twelve recovery words on paper, in order. Anyone with these words controls the wallet.
  3. Choose a password. It encrypts the words on this device only; Rivers cannot reset it.
  4. Press Test RVRB on the portfolio page to receive coins from the faucet.

Rivers staff will never ask for your recovery words. Never type them into any site except Rivers Wallet's restore screen.

Borrowing safely

The Lend page shows a health figure for each loan. Health is the collateral value at the liquidation threshold divided by the debt. Above 1 the loan is safe; below 1 anyone can repay up to half of it and take collateral plus a 5% bonus. Prices come from a pool average, so they move more slowly than the spot price. Repay or add collateral well before health reaches 1.

Launch a token

Token Studio in Rivers Scan creates a new coin without writing code.

  1. Enter the name, symbol, decimals, description and starting supply, and choose whether more can be minted later, up to a cap or not at all.
  2. Optionally set a team share. It is locked in a vesting schedule with a 12-month cliff and release over 36 months.
  3. Optionally open a starting pool against USDs, which sets the first price.
  4. Sign with your wallet. The token appears in Scan and can be swapped in the wallet.

Token Studio publishes a new Move package for each token. The creator keeps the right to mint and burn only if the token allows minting; the token page in Scan shows its supply rules.

Validators

Requirements

ItemRequirement
ServerUbuntu 24.04, 4 cores, 16 GB memory, 500 GB SSD, public IPv4
Open portsTCP 8080 and 8081; UDP 8081, 8082 and 8084
Stake10,000 RVRB, your own or delegated
Fees2 RVRB in the validator account

Steps

  1. Open validator-setup.sh, set VALIDATOR_NAME, RIVERS_RPC and RIVERS_INDEXER at the top, and paste the file into your server provider's user data box.
  2. After about 15 minutes, read /var/lib/rivers/VALIDATOR.txt on the server. Store the twelve words offline, then delete the file.
  3. Send 2 RVRB to the validator account. The server registers as a candidate.
  4. Stake 10,000 RVRB to the account from Rivers Validator's Join page. The validator enters the committee at the next epoch.

Staying in

A validator whose stake falls below 5,000 RVRB is removed after 7 epochs; below 2,500 RVRB it is removed at once. Rivers Validator shows how many of the latest checkpoints your node signed, your rewards per epoch and your delegators.

Connect for institutions

Joining

The Rivers foundation admits each institution to the network with its name, city, country, tier and a payment limit. The institution's wallet address becomes its member identity. Signing in to Rivers Connect with that wallet opens the member pages.

Sending a payment

Choose the receiving institution, the coin (NGNs or USDs on testnet), the amount, a reference of up to 35 characters and a four-letter ISO purpose code such as SUPP or SALA. For a batch, paste one payment per line as address,amount,reference,purpose; all lines settle in one transaction.

Reading payments in your systems

Every payment emits a Payment event with a running number. Connect exports each one as an ISO 20022 pacs.008 message. To read events directly:

GET {indexer}/events?module=network&name=Payment&addr={your address}

Calling the contract

rivers_connect::network::pay<T>(
  net: &mut Network,        // the shared Network object
  payment: Coin<T>,          // the coin to send
  to: address,              // receiving member
  reference: String,        // up to 35 characters
  purpose: String,          // up to 4 characters
)

The call fails if either institution is not a member or is suspended, if the amount is over the sender's limit, or if the network is paused.

Developers

Rivers speaks the Sui protocol, so the Sui TypeScript SDK and the Sui CLI work with it. The native coin type is 0x2::sui::SUI, shown as RVRB. Browsers reach nodes with gRPC-Web.

import { SuiGrpcClient } from '@mysten/sui/grpc';
import { Transaction } from '@mysten/sui/transactions';

const client = new SuiGrpcClient({ baseUrl: RIVERS_RPC, network: 'testnet' });

// Send 1 RVRB
const tx = new Transaction();
const [coin] = tx.splitCoins(tx.gas, [1_000_000_000n]);
tx.transferObjects([coin], RECEIVER);
const result = await client.signAndExecuteTransaction({ transaction: tx, signer: keypair });

Package and object addresses for the DEX, lending, Connect and vesting change when the testnet is reset. Read them from the indexer:

GET {indexer}/config
